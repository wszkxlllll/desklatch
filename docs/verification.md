# DeskLatch 首版验收记录

11 月 19 日的首轮模型实验采用测试程序创建的表单。11 月 20 日又使用真实博物馆网站、桌面 Office 和 E2B 云电脑，记录模型选择、实际派发和结果回读。开发环境为 Windows x64、Node.js 24.22.3 和本机 Chrome。

## 外部框架和真实模型

两个 JavaScript 宿主各自创建模型和运行循环，通过官方 API 调用智谱 `glm-5.3-flash`。模型同时可选 `observe` 和 `act`。请求数在发往模型的 HTTP 边界计数，图片数按该请求实际携带的图片计数。表单通过独立的 Playwright 读取判分，不使用模型的口头完成声明。

本机 Chromium 连续运行三个用例，同一命令的输出如下。

| 宿主与任务 | 模型请求 | 发给模型的图 | 工具调用 | 总 token | 浏览器实际结果 |
| --- | ---: | ---: | --- | ---: | --- |
| LangGraph，按名称填写两个字段 | 1 | 0 | 一次 `act` | 2,198 | 两个字段与本次指定值一致 |
| OpenAI Agents SDK，按名称填写两个字段 | 1 | 0 | 一次 `act` | 2,202 | 两个字段与本次指定值一致 |
| LangGraph，读图后展开筛选并填写随机码 | 1 | 1 | 一次 `act` | 3,183 | 展开和写入各通过一次程序核验，独立回读的六位码正确 |

读图用例由宿主先提供一张截图，随机码每次重建。零图用例的本地截图数也为零。宿主以页面结果或安全中断为停止条件，核验器只决定何时结束，不向模型补写动作或答案。

开发时遇到过两种失败。一次调用混用了 `type.text` 和 `setValue.value`，另一次只展开了界面，旧示例收到该批成功回执就过早结束。工具说明现已给出每种输入动作的完整形状，示例也分别处理单批完成和整项任务完成。在一次早期复跑中，LangGraph 到第三次模型请求才提交有效参数。上表是一轮实测值，成功率和费用降幅需要独立样本及对照。

## 真实馆藏检索与步骤复用

在 Windows 实机上，智谱从空白的 Chrome 打开用户给出的上博东馆参观指南，查到普通周二闭馆和 17:00 停止入场，再自行切换到 Word，把说明及官网链接写入本次已打开的空白 DOCX 并保存。一次委托用了 8 次模型请求，传图 0 张，正文写入和保存各一次。宿主从磁盘解析 DOCX，确认全文与模型提交的正文一致，两项事实和链接均正确。早期测试曾在一次成功保存后又写入相同的段落，因此复跑在落盘内容匹配时结束，并在轨迹中记录 `delivery.verified`。[实机验收入口](../examples/local-workspace-acceptance.mjs)

复跑时为 `ZHIPU_API_KEY` 配置智谱密钥，`DESKLATCH_RESULTS_DIR` 指向输出目录，`DESKLATCH_LOCAL_WORD_TEMPLATE_PATH` 指向由 Word 或 LibreOffice 保存的空白 DOCX。设置 `DESKLATCH_LOCAL_FOCUSED=1` 后运行 `node examples/local-workspace-acceptance.mjs`。程序复制空白文档并声明可用应用，模型经 `act` 选择 Chrome 或 Word 时才启动相应的独立窗口。测试缩小了正文的单次段数，要求模型实际使用续读和关键词查找。验收逐项核对成功的工具调用、Word 的派发回执及最终落盘的文档。

使用同一个上博官网页面做正文验证时，宿主将单次返回限制为 1 段。首读报截断，传回 `nextCursor` 后取得下一段。直接搜索“停止入场”可命中首段以外原文。应用清单可在未启动 Chrome 的情况下读取，调用 `act` 选中 Chrome 后才启动该浏览器。[上博东馆参观指南](https://www.shanghaimuseum.cn/mu/frontend/pg/service/visit-east)

按需启动的 Windows 实测使用智谱 `glm-5.3-flash`。会话开始时 Chrome 和 Word 的测试窗口均未启动。模型选择浏览器后，完成首批读取、一次续读和两次关键词查找，随后选择 Word，写入并保存说明。整个任务用了 9 次模型请求，传图 0 张。宿主核对了两个应用的进程与前台窗口、保存后的文档内容和引用的官网地址。[实机验收入口](../examples/local-workspace-acceptance.mjs)

同一问题也在托管 E2B Desktop 上跑通。智谱从空白 Chromium 打开东馆指南，读取网页正文，切换到已打开空白 ODT 的 LibreOffice Writer，写入中文说明并保存。共 12 次模型请求、0 张传给模型的截图，写入和保存各一次。下载后重新解析 ODT，正文与模型提交的文字一致，闭馆日、停止入场时间和所引官网均通过核验。默认模板缺少原生控件绑定，本次 Writer 操作使用经过焦点核验的窗口。测试使用独立的 Writer 配置关闭首次启动教程。开发中还复现过 SDK 键盘接口能写入英文、对中文返回成功但输入框仍为空的情况，因此本次使用授权的临时剪贴板传递中文，并独立读取成品。配置 `E2B_API_KEY`、`ZHIPU_API_KEY` 与结果目录后运行 `node examples/cloud-workspace-acceptance.mjs`。程序在结束时释放沙箱。[云端验收入口](../examples/cloud-workspace-acceptance.mjs)

工作区另测了从空白页开始的参观查询。LangGraph 向智谱 `glm-5.3-flash` 注册了 `observe` 和 `act`。用户只给了上博官网域名。模型主动打开官网，进入常设展览、青铜馆详情和东馆参观指南，并说明普通周二无法参观，建议改在周三下午 14:30 到东馆。独立核对确认了馆区、闭馆日、17:00 停止入场和四个实际查看的官网页面。本次有 15 次模型请求，使用了 6 次带截图的观察。这项验收的终点是给用户的答复。[可复跑的网页任务](../examples/workspace-website.mjs) · [上博东馆参观指南](https://www.shanghaimuseum.cn/mu/frontend/pg/service/visit-east) · [青铜馆详情](https://www.shanghaimuseum.cn/mu/frontend/pg/article/id/RI00004029)

## 宿主审批与独立安装

- 本机设置页实测了应用关闭、单窗口关闭、恢复应用后保留单窗口的设置，以及刷新后读回已保存的选择。验证按钮通过真实工作区检查示例窗口。站点验证调用临时 Chromium，依次验证了公开模式允许访问、指定模式名单外被拒绝、加入名单后允许访问。
- 同一公开浏览会话依次打开 Python 文档和 W3C 示例。访问一个测试进程创建的环回地址时，运行时返回 `private_address`，该测试进程收到 0 次请求。
- 在 W3C 的页内标签示例中，选择标签并核验成功后，DeskLatch 直接生成了零参数的点击缓存。刷新后通过同一对工具复用，浏览器捕获到一次点击。保持标签选中再请求复用，结果为 `already_satisfied`，新增点击为 0。智谱 `glm-5.3-flash` 也从观察中选择了缓存，三次模型请求后得到已核验的点击回执。另在 W3C 的折叠面板示例中验证了展开记录和已展开时跳过。[标签示例](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/examples/tabs-automatic/) · [折叠面板示例](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/examples/accordion/)

- 在原生 DSH 插件中登记两个编辑窗口和一个邮件入口。用户设置排除其中一个编辑窗口和整个邮件应用后，模型的应用清单只列出剩下的编辑窗口。直接传入被排除条目的 ID 也不会启动应用。把正在工作的窗口加入排除范围，再通过原工具尝试操作，派发计数保持不变。[DSH 验收用例](../test/dsh-plugin.test.mjs)

- 本机 Chromium 的合成页面接入智谱 `glm-5.3-flash` 做文字风险复核。写草稿由本地规则放行，“紧凑布局”经复核后实际切换，“Continue”后果不明，保持未执行且没有产生审批单。随后点击“Send summary”才产生唯一一张审批单，宿主拒绝后页面未发送。这个用例的两次复核共 357 token，截图数为 0。复跑入口为 `npm run verify:zhipu -- review`，需要宿主提供智谱密钥。

## 本地取证

在独立 Python 3.11 环境中，用 RapidOCR 3.10.0、ONNX Runtime 1.20.1 和 PP-OCRv5 mobile 检测／识别权重读取一张合成按钮图。关闭网络后，识别出的两行是“查询”和“Search”，置信度分别为 0.9977 和 0.9998。本机 Node 桥接两次实测各约 2.3–2.4 秒，包含新建 Python 进程和加载权重的时间。这是一次局部文字识别试验，置信度是模型对这两行的输出。

另一个执行测试打开动作前后本地留证。宿主的独立采集接口取得两张图片，模型侧收到零张，目标动作派发一次。动作派发后模拟存储故障，宿主收到留证失败诊断，已派发回执仍然保留。

## 托管 E2B Desktop 与智谱

2026 年 11 月 19 日，LangGraph 在宿主侧调用 `glm-5.3-flash`，经 DeskLatch 公共工具操作 E2B 云电脑上有窗口的 Chromium。每个用例使用新浏览器会话和合成表单。图片取自云端页面视口。核验器从同一远端页面另行读取字段，确认结果及模拟发送次数。

| 给模型的条件 | 模型请求 | 发给模型的图 | 执行器观察 | 实际结果 | 用例耗时 |
| --- | ---: | ---: | ---: | --- | ---: |
| 题面给出 Title、Notes，关闭取图 | 1 | 0 | 4 | 一次 `act` 写入两个字段，两项字段值分别通过 `expect` 核验 | 40.9 秒 |
| 宿主先给一张截图，题面给出筛选按钮和字段名 | 1 | 1 | 3 | 一次 `act` 展开筛选并输入截图里的随机六位码，远端回读一致 | 59.9 秒 |

耗时从表单就绪计至独立回读完成。这两项的控件名称已在题面中给出。模型可以直接按名称提出动作，执行器在每一步前读取页面并核对实际控件。第一项关闭取图，第二项允许继续取图。每个动作都由模型提出。

首次云测的两组任务都在第一步写入或点击前停止。用同一云端控件复查，滚动准备用了 2.8 秒，填写用了 4.4 秒，超过原先沿用的 1.5 秒本机时限，期间控件仍是同一节点。修正后，可见目标直接核对身份与遮挡，需要滚动时才滚动并复查。按名称查询仍检查候选的唯一性，只为匹配项取得操作句柄。

### 模型自行选择观察方式

下列云测都同时开放 `observe(controls/image/both)` 与 `act`。开始时只给文字任务，使用正常工具说明，由智谱决定是否观察、观察什么、如何拆步。图片采集数指新截取的张数，传输数按模型每次请求统计，同一张图随对话历史重传也计一次。

| 题面和页面 | 智谱实际调用顺序 | 模型请求 | 新截图 / 传输 | 远端回读 |
| --- | --- | ---: | ---: | --- |
| 给出两个字段名，仍允许取图 | 直接 `act` 写两项 | 1 | 0 / 0 | 两项正确，执行器内部另有 4 次控件观察 |
| 只说明交接目的，两个真实字段名带随机单据编号 | `observe(controls)` → 一次 `act` 写两项 | 2 | 0 / 0 | 两个目标名均来自前一轮工具返回，两个值正确，第三个归档字段保持原值 |
| 两个目标同屏，题面不给字段名，批次号只绘在画布上 | `observe(both)` → 一次 `act` 写两项 | 2 | 1 / 1 | 两个目标名均取自上一轮，批次号和交接说明正确，归档字段保持原值 |
| 批次号只绘在画布上，筛选输入框最初隐藏 | `observe(both)` → 点击展开 → `observe(controls)` → 填写 | 4 | 1 / 3 | 六位码正确。展开后的新控件经过查询，两步分两次 `act` |

交接任务的一次实际控件名称是 `Work summary 876933` 与 `For the incoming shift 876933`。模型收到的任务里只有要表达的意思和要填入的内容。筛选任务则暴露了一个协议差异：模型主动索图后，将图片直接放在工具角色下会被智谱 Chat Completions 拒绝。修正后，工具回复保留原始调用编号和文字，已授权的截图以注明来源的多模态消息交给模型。上表的筛选用例取自修正后的单独复跑。

同屏交接用例将批次号绘在画布上，同时给两个输入框加上独立的单据编号。首次试验中智谱只查文字控件，把字段名里的 `7051` 当作批次号。两项写入均符合模型自己给出的 `expect`，但独立核验发现画布真值是 `543763`，整题判失败。受管浏览器现会把具名画布与图片列为只读图形，提供其可访问名称，具体图像内容仍需获准取图。保持题面相同、更换随机数据后，智谱自行选择 `observe(both)`，再按返回的两个真实字段名称批量填写。复跑中只采集并传输了一张图，宿主独立回读通过，用时 62.4 秒。

## 复跑

仓库根目录下运行 `npm ci` 和 `npm test`。`npm run verify:package` 使用已缓存的依赖离线验证打包产物。真实模型试验需在宿主进程配置 `ZHIPU_API_KEY` 后运行 `npm run verify:zhipu`。`DESKLATCH_CHROMIUM` 可指向已安装的 Chromium。每次模型试验独立输出请求次数、图片数、实际工具轨迹、各步回执及页面核验结果。[真实模型试验](../examples/zhipu-acceptance.mjs)

托管云测还需 `E2B_API_KEY`。`npm run verify:zhipu -- e2b` 复跑固定图片条件，`npm run verify:zhipu -- e2b-choice` 复跑自主选择条件，也可追加 `choice-named`、`choice-discovery`、`choice-visible` 或 `choice-visual` 单测一项。每条命令创建一台沙箱，各题使用独立浏览器会话，最后释放沙箱并复查运行记录。
