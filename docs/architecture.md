# DeskLatch 运行时与宿主

## 依赖和权限

| 层 | 拿到的数据和权限 |
| --- | --- |
| 外部 Agent 框架 | 用自己的模型循环调用 `observe`、`act`。框架工具中没有改变权限、批准自己或运行脚本的入口。 |
| 宿主 | 选择已授权窗口、页面或云沙箱，创建会话并持有关闭、纠正、取消、审批入口。可以使用产品已有的手机或桌面审批界面。 |
| 执行器 | 校验整批参数、在当前观察中定位、逐步检查策略、派发、核验、产生回执。它只依赖 [后端契约](../src/contracts.ts)。 |
| 后端 | 提供特定范围内的观察和真实投递，在投递边界重新核对对象、焦点、遮挡及来源。宿主定义的能力授权和后端能力取交集。 |

定位使用当前界面。Plan、跨任务 Memory、Skill 和模型客户端由调用方管理。核心导入路径独立于 LangGraph、Agents SDK、MCP、Playwright、E2B 和本机 CUA。各框架适配器把同一对工具转换为该框架的原生工具。MCP 是跨进程协议，LangGraph 和 Agents SDK 分别保留各自的运行循环。

DSH 有两条接入路径。直接加载 Cordis 插件时，宿主通过 `openSession` 提供一份专属于此次挂载的已授权会话，工具在同一进程注册和执行，卸载时释放会话。这个适配器复用 DSH 官方的工具结果及附件转换函数。使用 MCP 时，由 DSH 官方客户端通过 stdio 连接 DeskLatch 服务。两种路径都由宿主管理配对、模型和人工批准决定，E2B 云电脑只提供执行环境。

## 多个应用共用的工作区

`desklatch/workspace` 将宿主登记的应用接到同一对 `observe`、`act` 上。每个应用有自己的 `DeskSession`，宿主提供激活和前台核验接口。浏览器还可提供限定来源的导航接口。模型能先查看可用目标，也能直接选择已经知道的应用标识。真实应用保留各自的控件和动作能力。

宿主可以用 `open` 条目登记尚未接入的应用。工作区列出条目的名称和 ID，并按宿主预先声明的能力提供工具参数。首次收到 `act({activate: id})` 时，才调用 `open` 接入已有的授权窗口或启动指定应用，拿到实际会话后按该会话的授权和当前前台检查执行。程序路径、文档路径和可接入的窗口由宿主选择。[Chrome 和 Word 的按需启动实例](../examples/local-workspace-acceptance.mjs)

切换成功后，工作区才把后续动作交给新应用。先前的控件引用随切换失效。模型可以观察当前页面的链接并按名称点击，也可以直接打开已知的网址。审批由原宿主处理，工具调用和执行回执带有应用标识，便于回查一次切换是谁发起、实际到了哪里。

LangGraph 和 OpenAI Agents SDK 会在绑定工具时读取参数格式。宿主应先登记本次任务允许使用的应用，再绑定 `workspace.tools`。执行时会按当前应用的实际能力检查每一步。如果运行中才加入具有新动作的应用，宿主需重新绑定工具才能向模型提供新增参数。MCP 宿主可以重新请求工具清单。

E2B 浏览器可用 DOM 定位。云端原生应用则从 AT-SPI 读取控件，按窗口标识和进程绑定。只能取得窗口时，观察会明确标记控件清单不完整。宿主可为一个指定窗口授权文字输入和 `Ctrl+S`，派发前核对系统键盘焦点和可见的阻塞弹窗。私有云桌面的中文输入还需要 `allowTemporaryClipboard`。运行时只在系统剪贴板空闲时临时取得所有权，向经过窗口或 X 客户端身份核实的接收方提供文字，完成后释放。应用是否保存成功，可由宿主回读已授权的目标文件确认。

## 正常执行和中断

1. 已知名称或角色时可直接调用 `act`。优先精确匹配实际名称和关联标签。局部范围可核实、目标唯一且是低风险筛选动作时，才可使用受控的“搜索／查询”等价关系。有歧义就返回候选。
2. `observe` 默认给文字控件。图像需要宿主明确授权。模型已经有图时可以提交图上的点；后续步骤使用同一批的控件条件或经核实的焦点，执行器自行重新观察。后端支持的动作组合直接决定模型能选择的工具参数。

   受管网页只遍历获准文档范围，展示可交互控件和具名只读图形。初始控件清单默认最多 100 项，定向查询默认检查前 500 个候选。两项分别受 `observeLimit` 与 `searchLimit` 配置约束，截断时返回 `complete:false`。画布上的文字不会自动成为控件值。Windows 全桌面适配器对每个获准窗口向 UIA 请求最多 512 个节点、最深 32 层，覆盖度取决于应用和驱动实际公开的控件。

   `observe({read:{query:"..."}})` 在当前授权页面的已渲染正文里查找字面关键词，返回匹配附近的原文和来源。顺序读取与关键词结果都按文本预算分页。续读使用 `document.nextCursor`，游标绑定到原始浏览器会话、页面和正文版本。页面切换或正文变化后可以重新发起查询。
3. 执行器在第一步前校验整批格式、预算、能力和焦点引用顺序。界面是否已经加载、目标是否可编辑、焦点有无变化，在各步派发前检查。派发后可用 `expect.state` 或公开字段的 `valueEquals` 做只读检查。
4. 需要审批时先停在该步，保留前面步骤的回执。宿主得到请求编号并展示对象、动作和允许展示的参数。受管浏览器对可识别的提交表单绑定实际参数，并可向审批界面展示站点和脱敏收件人。宿主可当场决定或稍后回传。批准仅消费一次。恢复时重新核对绑定对象和授权，取消、超时或对象发生实质变化时本步保持未派发。
5. 后端须区分已投递、明确未投递、部分生效和结果未知。应用效果只在有相应证据时标为 `verified`。检查失败时保留该动作的投递事实。发生远程超时或结果未知时不会自动重放。

## 后端范围

- **受管浏览器**持有宿主指定的 Page。控件模式读取 DOM，公开值可单独配置。截图、页面来源和宿主审批分开授权。
- **Windows 全桌面**按宿主给定的 PID／窗口句柄列表工作。前台输入和截取整个桌面需要各自的授权。宿主可沿窗口的所有者关系查找同进程新弹出的顶层对话框，再为实际选中的句柄建立独立授权。父窗口被遮挡时，发往父窗口的动作仍会停止。只读控件不依赖屏幕截图。
- **Windows 原生对话框**可选用 `native-uia-v1`。宿主先授权具体的 PID 和窗口句柄。`click` 调用控件公开的按钮或选项接口，`setValue` 修改可写字段。审批绑定控件身份和当时的对话框内容。真正派发前，执行器再次核对文件名等关键信息，并检查落点是否被其他窗口或控件遮挡。模型沿用 `observe` 和 `act`。
- **CUA 后台窗口**使用独立的 Windows WPF 适配器，限定到原生驱动 0.54.0 已验证的左键单击、单行输入和纵向按行滚动。
- **E2B 受管浏览器**接收宿主已持有的沙箱，通过已认证的命令流连接独立 Chromium，复用同一浏览器后端。匿名管道传递浏览器协议消息。模型只获准操作该页面，沙箱生命周期由宿主管理。云端单个浏览器动作默认允许 15 秒，可用 `browser.actionTimeoutMs` 调整。宿主另行控制整批动作的时间预算，真实云测示例使用 90 秒。

## 审查与留证

每一步先用本地规则检查动作、目标和已知后果。普通编辑和有结构依据的页面浏览可以直接执行。对于后果不明的动作，宿主可用 `createRiskPolicy({ reviewer })` 接入自己的文字审核器，也可提供局部 OCR。审核器判明低风险时动作继续，识别到高风险或宿主明确要求同意时才发出 `approval_required`。宿主禁止的操作直接停止。

证据仍然不足、复核超时或预算耗尽时，本步返回 `risk_evidence_required`，没有派发，也没有审批单。Agent 可以查看相关控件，选择后果更清楚的入口。比如表单输入框里的回车可能提交数据，改用实际提交按钮就能核对该按钮及其提交内容。没有新证据就保留未执行状态，之前已执行的步骤仍有各自的回执。

核心默认在本地判断。启用补查后，一次风险判断至多做一次局部 OCR 和一次文字复核。宿主可用 `maxExternalRequests` 对同一策略实例设置累计上限。文字审核器接收动作摘要、控件信息和可选的局部 OCR 文字，输入参数中的正文只提供长度。截图、执行侧留证和向模型提供图像分别授权。启用审计时，由宿主提供受限的存储、脱敏器和保留策略。

宿主可以允许模型自行选择读控件或取图。智谱 Chat Completions 要求图片放在用户侧的多模态输入里。LangChain 适配器可在模型请求边界把已授权的 `observe` 图片附在同一批工具回复之后，并注明来源和原始调用编号。这个转换只处理已有图片，不会触发新的截图、模型调用或动作。

## 可选的步骤复用

宿主可从 `desklatch/reuse` 创建记录器，让原有工具把 `act` 委托给记录器。它调用当前会话执行动作，并将回执与这次实际请求相绑定。首版支持按控件条件定位的 `type` 和 `setValue`。例如，写入一个查询词后，只有同一输入框的公开值与查询词相等，且整批操作均已核验，宿主才能保存这段步骤。记录里保存参数名，实际查询词在本次运行时提供。

遇到相似任务时，宿主选中记录并提供本次参数。记录器把新的请求交回公共 `act`。执行器在当前界面重新定位，每一步都经过本次权限、风险判断和结果检查。旧坐标、控件引用以及之前的批准只在原执行中有效。运行回执说明本次实际执行到了哪一步，命中记录本身不能说明任务成功。

例如，宿主用 `createVerifiedStepReuse({ session, store })` 创建记录器，再将 `createDeskTools({ ...session, act: reuse.act })` 交给现有框架。选择哪条记录、适用哪个应用和工作区域、参数从哪里来，均由宿主负责。独立安装的验收程序在没有任何框架、浏览器或模型 SDK 的环境里执行、记录并复用了一个字段写入。[独立安装验收](../scripts/verify-package.mjs)
